# 개요

## filequeue란

**filequeue**는 하나의 파일시스템 디렉터리를 큐로 사용하는 C 라이브러리다. 프로세스/노드 간
메시지를 파일로 주고받으며, **공유 디스크** 위에 큐를 두어 한 노드가 죽어도 다른 노드가
이어받는 **failover**를 제공한다.

별도의 브로커 데몬이나 데이터베이스가 필요 없다. 메시지 = 파일, 큐 = 디렉터리이며, 모든 상태
변화는 파일시스템의 원자적 연산(rename, unlink)만으로 이루어진다. 따라서 어느 시점에 크래시가
나도 큐는 일관된 상태를 유지한다.

## 전달 보장 모델

filequeue는 두 가지 핵심 속성을 보장한다.

| 속성 | 값 | 의미 |
|---|---|---|
| **전달 보장** | At-least-once | 메시지는 **최소 1번** 처리된다. 유실은 없으나 장애 시 **중복**될 수 있다. |
| **Failover** | Active-Passive | 한 시점에 **활성 소비자 1개**만 동작하고, 그 노드가 죽으면 대기 노드가 인수한다. |

> **소비자 멱등성(idempotency)은 계약 조건이다.** At-least-once는 장애 복구 시 같은 메시지를
> 다시 전달할 수 있으므로, 소비자는 같은 메시지를 두 번 처리해도 결과가 같도록 작성해야 한다.

## 적용 대상과 전제

- **공유 디스크**: SAN LUN, 클러스터 공유 볼륨, NFS, SMB 등 두 노드 이상이 같은 파일에 접근할 수
  있는 스토리지. (토폴로지에 따른 차이는 [Failover 운영](#failover-운영) 참고)
- **의존하는 원자성**: 같은 볼륨 내 `rename`의 원자성, 배타 생성(`O_EXCL`/`CREATE_NEW`)의 원자성.
  새 스토리지를 도입할 때는 `test_atomicity`로 이 전제를 먼저 검증해야 한다.
- **플랫폼**: POSIX(Linux, Cygwin)와 네이티브 Windows(Win32). 빌드 시 자동 선택된다.
